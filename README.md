# 🧠 Open-Domain Debater Assistant

A Retrieval-Augmented Generation (RAG) system that takes any debate topic,
retrieves relevant real-world arguments for and against it, classifies each
argument's rhetorical style, and generates separate **Point / Counterpoint**
summaries.

---

## How It Works

```
User enters a topic
        │
        ▼
Topic → embedding (all-MiniLM-L6-v2)
        │
        ▼
FAISS similarity search over 100,000 pre-embedded arguments
        │
        ▼
Top 5 arguments retrieved, each classified as
ETHICAL / LOGICAL / EMOTIONAL (facebook/bart-large-mnli)
        │
        ▼
Arguments split by stance (PRO / CON)
        │
        ▼
Two separate summaries generated (facebook/bart-large-cnn)
```

**Dataset:** [args.me corpus](https://zenodo.org/records/4139439) — ~100,000
cleaned, filtered English debate arguments sourced from Debatewise, IDebate,
Debatepedia, and Debate.org, covering ~29,000 distinct topics.

## Setup

### 1. Install dependencies
```bash
python -m venv venv
venv\Scripts\activate        # Windows
pip install -r requirements.txt
```

### 2. Download the raw dataset
This project uses the [args.me corpus](https://zenodo.org/records/4139439)
(~867 MB, not included in this repo due to size). Download
`argsme-1.0-cleaned.zip`, unzip it, and place the JSON file at:
```
data/raw_argsme/args-me-1.0-cleaned.json
```

### 3. Build the index (one-time, ~1.5–2 hours on CPU)
```bash
python app/build_index.py
```
This filters out spam/gibberish/offensive content, generates embeddings for
~100,000 arguments, and saves the FAISS index + metadata CSV to `data/`.

### 4. Run the app
```bash
streamlit run app/app.py
```
Or, for a quick terminal test without a browser:
```bash
python app/cli_demo.py
```

**Note:** On first run, the classification model (`bart-large-mnli`) and
summarization model (`bart-large-cnn`) will download from Hugging Face
(~2 GB total). This only happens once.

## Design Notes & Known Limitations

Being upfront about the trade-offs, since every RAG system has them:

- **FAISS always returns *something*.** If a topic isn't well-represented in
  the dataset, the app shows the closest available matches along with a
  low-relevance warning, rather than pretending it found a perfect answer.
- **Confidence scores are real, not placeholders.** The classification
  confidence comes directly from the zero-shot model's output — it's often
  in the 0.3–0.5 range because the model is genuinely uncertain when an
  argument could reasonably fit more than one category, and reporting that
  honestly seemed better than showing an inflated fixed number.
- **PRO/CON stance is relative to each argument's original source topic**,
  not necessarily framed identically to whatever the user typed. This is a
  known nuance of building on top of pre-labeled data, and one you might
  want to improve if you fine-tune this further.
- **Summarization quality depends on retrieval quality.** If the top 5
  retrieved arguments are weak, the summary will be too — this is inherent
  to RAG systems, not something a bigger model alone fixes.

## Tech Stack

| Component | Tool |
|---|---|
| Embeddings | `sentence-transformers` (all-MiniLM-L6-v2) |
| Vector search | `faiss-cpu` |
| Classification | `transformers` zero-shot pipeline (facebook/bart-large-mnli) |
| Summarization | `transformers` summarization pipeline (facebook/bart-large-cnn) |
| UI | `streamlit` |
| Evaluation | `rouge-score`, `nltk` (BLEU) |
